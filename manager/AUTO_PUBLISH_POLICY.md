# PY-authorised publishing policy

PY explicitly instructed: "i need auto upload please do not wait for me".

For the original-site integration in PR #6, this is approval to complete the checks, merge and publish to the existing Netlify website without asking for a second confirmation.

For subsequent routine website changes expressly requested by PY, the operating default is: implement in the existing repository, inspect the diff, run applicable brand/content/security/build/browser checks, then publish without another conversational approval request. This is not permission to invent or publish unrequested content.

Keep prices, payment destinations, legal/privacy terms, customer data, core brand assets and chart rules unchanged unless the particular change is expressly authorised. Do not enable paid services, disclose credentials or bypass repository rules/security failures.

GitHub Actions and Netlify remain the execution infrastructure. A merged PR is not proof of a successful live deployment. Verify the production response and customer-facing flows. Report failures honestly, retain a rollback commit, and repair a routine technical issue within the authorised scope rather than waiting for PY to repeat the request.

This policy supersedes generic second-confirmation language for authorised routine website updates only. It does not disable technical guardrails, broadly change ChatGPT plugin permissions, or activate unattended AI article publishing.
